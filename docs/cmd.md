**Studio — Product Delivery System**
**Tags:** #DesignOps #ProductSystems #AIWorkflow #DeliveryInfrastructure

### Definition

Studio is a structured internal workspace that organizes how product systems are designed, reviewed, and delivered across teams.

Studio creates a clear boundary between two critical environments:

* Client-facing prototypes (focused, evaluative, simplified)
* Internal product system workspace (full context, design system, experimentation, multi-prototype visibility)

Clients never navigate Studio directly. They receive targeted prototype links. Studio is internal infrastructure.

### Core Capabilities

* Prototype orchestration across multiple product domains (Member, Accounting, Underwriting, Agent, Renewals)
* Modular product development (each system evolves independently within a shared structure)
* Shared internal navigation shell across all product initiatives
* Living design system integration directly within the workspace
* Context-rich prototype metadata:
  * Status (In Progress, etc.)
  * Audience (Stakeholders vs Engineers)
  * Domain tags (Billing, Claims, Cases, etc.)
  * Last updated timestamps
* Side-by-side concept comparison via prototype hub
* Synchronization between prototypes, design system, and real application codebase

### Structural Pattern

Studio functions as a **control plane for product development**:

* Centralizes visibility across initiatives
* Enables parallel product tracks
* Reduces dependency on external communication for context
* Eliminates ambiguity around system ownership and state

### Workflow Impact

* Reduces Slack / meeting overhead by embedding context directly into the system
* Allows designers and engineers to operate with shared visibility
* Enables rapid iteration without exposing internal scaffolding to clients
* Supports AI-assisted workflows by maintaining structured, reusable context
