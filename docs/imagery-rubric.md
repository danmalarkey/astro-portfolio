# Imagery Rubric (Homepage + Future Work Pages)

Last Updated: February 22, 2026

## Purpose

Define what "good imagery" means for this portfolio so visual decisions support Dan's positioning:

- strategic + tactical design leadership
- business impact
- systems thinking
- premium but not generic presentation

## Core Principle

The image is not decoration.

Each image should prove something:

- craft quality
- product complexity
- operational clarity
- system thinking
- decision quality
- business impact context

## Image Categories (Use Intentionally)

### 1. Product UI Crops (Primary for craft-forward work)

Use when:

- interface quality is genuinely strong
- the screen demonstrates complexity or system coherence

Best practices:

- crop tightly (show decisions, not the whole monitor)
- use consistent aspect ratios in a section
- prefer 1-2 strong views over many weak screenshots
- highlight the part of the interface that supports the stated outcome

Avoid:

- full artboard dumps
- tiny text/screens that read as texture only
- "pretty but unrelated" screens

### 2. Systems / Process Artifacts (Primary for operational impact work)

Use when:

- the work's value is workflow redesign, alignment, architecture, or decision-making
- the final UI is not the strongest proof of value

Examples:

- workflow maps
- service blueprints
- reporting architecture diagrams
- IA maps
- decision trees
- process state comparisons
- implementation/system documentation excerpts

Best practices:

- annotate key areas
- simplify visual noise
- frame the artifact as proof of leadership/clarity

Avoid:

- dumping dense diagrams without guidance
- using artifacts that expose sensitive internal details

### 3. Outcome Context Imagery (Secondary / supporting only)

Use when:

- industry context adds meaning (insurance, logistics, restaurant ops, etc.)
- you need a visual bridge while core proof assets are limited

Best practices:

- keep these secondary to product/systems evidence
- use sparingly in featured outcomes

Avoid:

- generic "people in office" stock as the main proof image

### 4. Portrait / Personal Imagery (Brand / About / Writing)

Use when:

- the goal is connection, voice, or personal brand depth
- the page is about Dan (About, Writing, personal features)

Avoid:

- using portrait imagery where evidence of work should lead

## Proof-First Selection Checklist (Per Featured Outcome)

Before choosing an image, answer:

1. What does this outcome need to prove most?
2. Is the strongest proof visual craft, systems thinking, or operational impact?
3. What image would help an executive trust this in under 5 seconds?
4. What image would help a design leader respect the depth of work?
5. What can be safely shown publicly?

## Recommended Asset Set per Outcome (Minimum)

For each featured outcome, gather:

- 1 primary image (homepage card / hero proof)
- 1 alternate image (fallback if card crop fails)
- 1 support artifact (for deeper case page/writing)
- 1 short annotation note:
  - what this image proves
  - what should be cropped/highlighted

## Visual Consistency Rules (Homepage)

- Keep image treatment consistent across the rail:
  - ratio family
  - tonal grading
  - edge/radius treatment
- Do not force all outcomes to look equally polished
- Do ensure all outcomes look intentionally art-directed

This is a leadership portfolio, not a Dribbble gallery.

## Handling "Ugly but High-Impact" Work (Important)

When the UI is visually rough but the impact is high:

- do not hide it
- do not oversell it as a craft showcase
- shift the proof frame to:
  - process clarity
  - operational leverage
  - speed/risk reduction
  - system-level decisions

Use imagery that communicates complexity and transformation, not cosmetic polish.

## Future Workflow (Recommended)

1. Tag each featured outcome as `Visual`, `Systems`, or `Hybrid`
2. Build an asset list before editing any screenshots
3. Art-direct crops to match the proof claim
4. Validate each image against executive and design-leader lenses
5. Only then finalize homepage imagery
